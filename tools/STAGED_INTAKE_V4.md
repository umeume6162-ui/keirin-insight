## Established two-of-three verification and adaptive source selection

- Restore the previously established verification threshold: agreement on required fields across at least two distinct sites within a three-site comparison set is a verification pass. Three matching sites are an S candidate; two matching sites are an A candidate. Two successfully compared matching sites suffice; a third fetch is not required solely to repeat a completed check. A traceable single-site observation remains provisional (B/B+ according to the existing evidence rubric); material unresolved conflict is C, no evidence is D. Retain actual source observations, URLs, timestamps, retrieval methods and normalization results. - Select comparison sites dynamically by field and availability instead of fixing the same three sites for every task. Optional missing fields are not a reason to reject an otherwise complete required-field comparison. Reuse existing source-performance records and avoid duplicate registries. Start with the previously established preferences, then change rankings only on observed results. Distinguish different publication sites from proven upstream evidence independence; never claim independence without evidence.
- A verification pass is the established two-of-three content comparison, not an additional discretionary approval loop. Move eligible passes promptly through the existing approval/publication transition and verified synchronization pathway, without repeating the same comparisons simply because a chat moved. Preserve the existing publication safety checks, field-specific primary-source requirements for higher evidence grades, and separate learning eligibility; report any technical gate that still blocks delivery and repair that integration rather than asserting a pass has automatically been published. Pending or materially conflicting fields must not be represented as verified. Update shared progress so both execution paths resume unresolved work instead of repeating completed comparisons.
