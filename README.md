### 引き継ぎ時の確認順

1. 上記の正式仕様書を読む。既存の判定基準を勝手に新設・改変しない。
2. 本番シートの最新受付数・収集済み開催数・レース数、保留・承認済み件数を実際に読み取る。古い数値を確定値として引き継がない。
3. 手動・自動の両方の受付を横断し、同じ選手・レースを重複登録しない。
4. 直近のコード変更・テスト結果・未解決不具合を確認。修理優先、ただし影響のない収集・照合・同期を不必要に止めない。
5. 「3サイト中2サイト一致」の既定基準で必要項目を照合し、対象項目に適したサイトを実績に基づき選ぶ。完了分を同じ理由で延々と再照合しない。
6. 照合合格分は既存の承認・公開ガードと同期契約に従ってサイト反映へ進める。取得・保存・照合合格・正式承認・公開を別々に報告。
7. 手動は自動実行の追加処理。両者で同じ仕様・研究成果・サイト評価を使用する。

**正式な仕様書の改定先は `tools/STAGED_INTAKE_V4.md`。** スプレッドシートの「KI｜引き継ぎ・共通仕様」は入口と要点の控えであり、矛盾した場合は最新版の正式仕様書と実際のコード／台帳を照合して解決する。チャット移行はリセットの理由にならない。
